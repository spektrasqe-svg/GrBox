# Разбор проекта GrBox / SECRET BOX® — код + воронка продаж

> Дата: 2026-10-09. Сделано вручную, по фактическому коду (не по докам). Цель — понять, как
> устроено приложение и **почему сайт пока слабо продаёт**, вынести на обсуждение до правок.

---

## 1. Карта кода (как всё устроено)

Автономные HTML-страницы поверх общего движка в `assets/site/`. Без сборщика, без фреймворка,
внешняя зависимость — только three.js (UMD/CDN).

### Ядро (читают друг друга в этом порядке)

| Модуль | Глобальный объект | Роль |
|---|---|---|
| `site-config.js` | `SB_CONFIG` / `SB_PRICE` / `SB_CONTACTS` | **Единая точка правки**: контакты, приём заявок, цены. Всё остальное читает отсюда |
| `product-state.js` | `SECRETBOX` | Текущая конфигурация (localStorage v2 + миграция v1). Свои `geometry/mass/estimate/label` |
| `parametric-layout.js` | `SECRETBOX_LAYOUT` | Параметрическая геометрия: зоны, якоря, проверки совместимости, метрики (масса/мощность/воздух/пол/тепло) |
| `project-engine.js` | `SECRETBOX_PROJECT` | **Официальная СПЕЦИФИКАЦИЯ**: BOM-строки, totalPrice, totalMass. Экспорт txt/json |
| `leads.js` | `SB_LEADS` | Заявка: сводка конфига, валидация, сборка текста, отправка (links/formspree/webhook/telegram) |
| `account.js` | `SB_ACCOUNT` | Личный кабинет (localStorage): профиль, проекты, заявки |
| `platform-shell.js` | — | Шапка/навигация (8 разделов + КАБИНЕТ + CTA), `?bare=1` |
| `3d-bom-bridge.js` | `__SECRETBOX_BOM_BRIDGE` | Связка 3D ↔ BOM (тап по детали → строка спецификации) |
| `ru-localization.js` | `SECRETBOX_RU` | **Рантайм-перевод EN→RU** регулярками по текстовым нодам (см. §4.6) |

### Страницы (воронка)

```
index.html      → витрина: герой, принципы, showcase, мини-конфигуратор, разбор, 3D, инженерия, CTA #order
product.html    → один продукт + 3 комплектации (БАЗА 80k / ПОЛНЫЙ 150k / МАКСИМУМ 300k)
builder.html    → конфигуратор «с нуля» + живая 3D (postMessage) → сохранение проекта → заявка
order.html      → ФОРМА ЗАЯВКИ (точка конверсии) + сводка конфига + «что дальше»
account.html    → возврат: профиль, проекты, история заявок
engineering.html→ метрики + СПЕЦИФИКАЦИЯ из живой конфигурации
calculators.html→ 5 калькуляторов (воздух/свет/VPD/тепло/пол)
growpedia.html  → база знаний (6 статей)
documentation.html, GrowBox_v31_3D.html (3D-вьюер)
```

Поток продажи: **index → (product | builder) → order → заявка → Telegram**. `account` — для
возвратных. Всё ведёт на `order.html`.

## 2. Что сделано хорошо (не трогать)

- **Единая точка коммерции** (`site-config.js`) — цены/контакты/режим заявок правятся в одном
  месте, страницы подхватывают через `data-sb-price`. Грамотно для «плавающих цен».
- **Живой конфигуратор + 3D** — связка builder↔iframe через postMessage без сброса камеры.
  Это сильная фишка, конкуренты редко так делают.
- **Инженерная достоверность** — формулы, проверки совместимости (LIGHT_WIDTH, FLOOR_LOAD…),
  СПЕЦИФИКАЦИЯ из реального движка. Это не «AI slop», у сайта есть своя идентичность.
- **Воронка продумана**: типы запроса с ценами прямо в селекте, сводка конфига в сайдбаре,
  «что дальше», согласие на данные, профиль автоподставляется из кабинета.
- **Кабинет без регистрации** — localStorage, проекты экспортируются в txt/json.

## 3. Воронка продаж — разбор (главная тема)

### Сильные стороны
Витрина объясняет продукт, есть живая цена, есть 3 точки входа в заявку, форма низкого
порога (имя + 1 контакт).

### Слабые стороны (почему «мало упора на продажу»)

**S1. 🔴 Заявки физически никуда не уходят.**
`leads.mode='telegram'`, но `endpoint=null` → в `submit()` условие `(mode)&&endpoint` ложно и
всё молча падает в режим `links`: пользователь получает «Заявка готова» + кнопку «скопировать».
Т.е. лида нужно **вручную** скопировать и самому отправить в Telegram. Это убивает конверсию —
настоящий покупатель на 150–300k ₽ не будет копировать текст. **Это главный продаженный блокер.**

**S2. 🟠 Позиционирование противоречит само себе.**
Весь нарратив — «один параметрический продукт, готовых моделей нет». Но в герое index висят
остатки старого:
- hero-stats: «**3 модели корпуса**» (а должно быть «20+ параметров»)
- плашка на фото героя: «**Модель A · шоколад / паутина**»
Покупатель видит «3 модели», заходит в product — там «моделей нет, всё индивидуально». Диссонанс
= недоверие. Нужно вычистить.

**S3. 🟠 Нет доверительных элементов (trust).** Для покупки 150–300k ₽ критично, а на сайте нет:
- отзывов / кейсов / «как это выглядит у клиента»
- гарантий, сроков, доставки/монтажа («под ключ» обещано, но не раскрыто)
- FAQ на витрине (люди боятся: шум? запах? электрика? вода? соседи?)
- «кто мы / почему нам можно» (хотя бы короткий блок)
Инженерия подана как спеки, а не как **выгода**: «−34 дБ → спите в соседней комнате» продаёт
лучше, чем «акустический тракт».

**S4. 🟡 CTA слишком мягкие.** «ЗАПРОСИТЬ РАСЧЁТ» — это «потом». Нет:
- альтернативного быстрого действия («написать в Telegram сейчас», «узнать цену за 30 сек»)
- ограничения/срочности («сборка от N дней», «запись на месяц»)
- квиза-сборки с финальной ценой как якоря (мини-конфиг есть, но не доводит до заявки)

**S5. 🟡 Мини-конфигуратор на главной не доводит до заявки.** Он считает ≈цену, но CTA из него
ведёт в builder/order общо, не «передавая» собранную конфигурацию как готовый лид.

**S6. 🟡 SEO/трафик.** Навигация целиком инжектится JS (`platform-shell.js`) → поисковики видят
страницы без меню/ссылок. Для продаж органикой это минус. Hero-текст тоже частично JS.

### Что предлагаю обсудить (приоритет продаж)
1. **Задеплоить Telegram-релей** (S1) — чтобы заявки падали в Telegram автоматически. Требует
   твоего токена бота. Это №1 по влиянию на продажи.
2. **Вычистить позиционирование** (S2) — убрать «3 модели/Модель A», свести к «один BOX под ваш размер».
3. **Добавить trust-блок** (S3) — отзывы/кейсы, гарантии+сроки, FAQ, «выгода, а не спеки».
4. **Усилить CTA** (S4/S5) — живой Telegram-виджет/кнопка, быстрый квиз, передача конфига в заявку.
5. **SEO** (S6) — вынести навигацию/тексты в статику.

## 4. Технические находки (достоверность данных)

**4.1 🔴 Три разные формулы массы — разброс 161 кг на одном шкафе.**
Замерено на конфигурации по умолчанию (1250×2060×741):
- `product-state.mass()` (объёмная): **371 кг**
- `parametric-layout` floorMass (площадь панелей): **256 кг**
- `project-engine` totalMass (сумма строк BOM): **210 кг**

Где что видит человек:
- **Сводка заявки** (`leads.configLines`) и кабинет → `product-state` = **371 кг**
- **builder / engineering / СПЕЦИФИКАЦИЯ** → `project-engine` = **210 кг**

Т.е. клиенту в заявке уходит **371 кг**, а в спецификации — **210 кг**. Противоречие в глазах
покупателя + неверная нагрузка на перекрытие (ключевая инженерная метрика!). Нужно свести к одной
формуле (правильная — площадь панелей, её и оставить; остальные переписать на неё).

**4.2 🟡 Две модели цен структурно, откалиброваны в 3 точках.** `estimate()` (product-state) и
`totalPrice` (project-engine) — разные формулы, совпадают только на якорях 80/150/300. Между
точками могут расходиться. Плюс дефолты в `estimate()` (base 72000, SE3000 28000…) **не совпадают**
с `site-config` (base 47000, SE3000 25000) — срабатывают, если config не загрузился.

**4.3 🟡 `ru-localization.js` — хрупкий костыль.** Прогоняет regex-замену EN→RU по текстовым нодам
через MutationObserver. Ломает латиницу в подписях («smart-drip» → «УМНЫЙ-drip»), не тестируем,
трудно поддерживать. Правильнее писать тексты сразу на русском.

**4.4 🟢 Навигация инжектится JS** — FOUC + минус SEO (см. S6).

**4.5 🟢 Мелочи из прошлых аудитов, ещё живые:** three.js UMD/CDN (warning), тач-цели <44px,
базовый a11y, картинки `cab_*` не используются, футер «Москва · сборка под ключ»/«Стать дилером»
ведут во временный `#order`.

## 5. Вопросы владельцу (блокируют движение по продажам)

1. **Заявки:** деплоим Telegram-релей сейчас? Нужен токен бота (@BotFather). Или выбираем
   Formspree / webhook / оставляем ручной режим?
2. **Позиционирование:** подтверждаем «один BOX под размер» и чистим «3 модели»? Или модели
   всё-таки нужны как готовые конфиги?
3. **Доверие:** есть ли реальные фото/отзывы/кейсы, гарантии и сроки, которые можно показать?
   Кто целевой клиент (квартира? дом? это растения/травы?) — влияет на тон и FAQ.
4. **Цены:** оставляем якоря 80/150/300 как «стартовые комплектации»? Что с реальным прайсом?
5. **Слоган/тон:** герой «ПОКА ВСЕ ДУМАЮТ — ЭТО ШКАФ» — оставляем как визитную карточку?
